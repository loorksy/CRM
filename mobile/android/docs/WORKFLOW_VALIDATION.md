## فحص الواجهة والفقاعة

فُحصت شجرة الواجهة الفعلية عبر `uiautomator`، دون الاعتماد على ملفات XML سابقة:

- ظهرت شاشة «تدقيق الرواتب» واختيار/إنشاء دورة مسماة والأقسام الثلاثة: التدقيق والبحث والإرسال.
- ظهرت الفقاعة ومحررها القابل للكتابة وزر اللصق والعدد وشريط السرعة والاختصارات. ظهر افتراضي المحرر الجديد `100 رسالة / دقيقة`.
- أُدخل `First` ثم سطران ثم `Second`، فأصبح النص فقرتين وأظهر العداد `2 رسالة`.
- اختير الاختصار `300`، ثم نُفذ `force-stop` وأُعيد فتح الخدمة. أعادت شجرة الواجهة النص نفسه وعدّاد `2 رسالة` وسرعة `300 رسالة / دقيقة`؛ نجحت assertions على القيم الثلاث.
- لم يُضغط زر بدء الإرسال إلى محادثة، ولم تُختبر أي رسالة واتساب حقيقية.

المحاكي يعمل برمجياً دون `/dev/kvm`. أثناء أول إدخال لوحة مفاتيح في Compose رُصد ANR، وأظهر السجل تهيئة `KeyMappingKt`، كما تعثر تشغيل اختبار أصلي قبل تهيئة التطبيق. استُخدمت ترجمة ART المسبقة (`cmd package compile -m speed -f` للتطبيق وAPK الاختبار) قبل نجاح التحقق الأصلي وفحص الفقاعة. لا تثبت هذه النتائج أداء الكتابة في شاشة Compose أو سلاستها على هاتف فعلي. لقطات الصورة في هذه الصورة ATD كانت سوداء؛ دليل الواجهة هنا هو شجرة الوصول الفعلية والقيم المحفوظة، لا مراجعة بصرية للصورة.

- حساب Google حقيقي وOAuth أو قراءة/كتابة Sheets وDrive عبر الشبكة؛ صورة AOSP لا تحتوي Google Play.
